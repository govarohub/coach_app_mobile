# CK-019.9: Seguridad de reseñas en Firestore

## Reglas aplicadas

Las reglas se encuentran en `firestore.rules` y se registran desde
`firebase.json`.

| Operación | Política para `reviews/{reservationId}` |
| --- | --- |
| Leer/listar | Público; los documentos no contienen el UID del cliente |
| Crear | Usuario autenticado dueño de una reserva `completed`; coach coincidente; rating entero 1–5; comentario opcional de hasta 500 caracteres; timestamps de servidor |
| Editar | Mismo dueño y reserva completada; solo puede cambiar rating, comentario y `updatedAt`; conserva reserva, coach y `createdAt` |
| Borrar | Denegado |

El documento usa el `reservationId` como ID y no acepta campos adicionales,
incluido `clientId`. La propiedad se valida contra
`reservations/{reservationId}`. Las reseñas de un coach no pueden ser creadas
por el propio coach.

## Compatibilidad de permisos

La política desplegada mostrada en Firebase permite lectura y escritura a
cualquier usuario autenticado en las demás colecciones. `firestore.rules`
preserva esa política fuera de `reviews` y excluye reseñas del comodín para que
sus reglas específicas no queden anuladas. La revisión de permisos del resto de
colecciones queda fuera de CK-019.9.

## Migración previa al despliegue

Si existen documentos `reviews` creados con el esquema anterior, retirarles el
campo `clientId` antes de permitir lectura pública. Las ediciones realizadas
por la app también eliminan ese campo heredado, pero eso no protege documentos
antiguos antes de que se editen.

## Validación y despliegue

- Compilación local con `firebase emulators:exec --only firestore`: correcta.
- Despliegue de reglas: `firebase deploy --only firestore:rules`.
- Despliegue de índices: `firebase deploy --only firestore:indexes`.
- El despliegue remoto no se ejecutó como parte de CK-019.9.
- Las pruebas de autorización permitida/denegada quedan registradas para
  CK-019.10.
