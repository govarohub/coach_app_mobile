# CK-019.2: Modelo de datos de calificaciones y reseñas

## Estado

Definido para la primera versión de CK-019. La implementación corresponde a los
siguientes SUB-CK.

## Fuente de datos

Las reseñas se almacenan en la colección raíz `reviews`. Cada documento
representa la reseña de una reserva completada y su ID de documento es el
`reservationId`:

```text
reviews/{reservationId}
```

Usar el ID de la reserva como ID del documento aplica la regla de una reseña
por reserva en la estructura de datos y evita depender de una consulta previa
para detectar duplicados.

## Campos del documento

| Campo | Tipo Firestore | Requerido | Regla |
| --- | --- | --- | --- |
| `reservationId` | String | Sí | Igual al ID del documento y a `reservations/{reservationId}` |
| `clientName` | String | Sí | Nombre público tomado del perfil autenticado; máximo 100 caracteres |
| `coachId` | String | Sí | UID del coach de la reserva |
| `rating` | Integer | Sí | Entero entre 1 y 5 |
| `comment` | String | No | Omitido si está vacío; máximo 500 caracteres después de recortar espacios |
| `createdAt` | Timestamp | Sí | Hora de servidor de la primera creación; inmutable al editar |
| `updatedAt` | Timestamp | Sí | Hora de servidor de la última creación o edición |

Ejemplo:

```text
reviews/{reservationId} {
  reservationId: "<reservationId>",
  clientName: "<publicDisplayName>",
  coachId: "<coachUid>",
  rating: 5,
  comment: "Excelente sesión.",
  createdAt: <server timestamp>,
  updatedAt: <server timestamp>
}
```

Cuando no se escribe un comentario, el campo `comment` se omite. El documento
contiene el nombre público elegido para mostrar, pero no el UID, correo ni datos
de pago del cliente. La autoría se verifica consultando la reserva asociada y
comparando su `clientId` con el UID autenticado.

## Relaciones y validaciones

- `reservationId` referencia `reservations/{reservationId}`.
- `coachId` debe coincidir con la reserva referenciada.
- `clientName` es informativo y se obtiene del perfil autenticado; nunca se usa
  como prueba de autorización.
- La reserva debe estar en estado `completed` al crear la reseña.
- El cliente autenticado debe coincidir con `reservations/{reservationId}.clientId`.
- Al editar, `reservationId`, `coachId` y `createdAt` no cambian.
- `rating` y `comment` se pueden editar por el mismo cliente; cada edición
  actualiza `updatedAt`.
- La autorización y la validación definitiva se implementarán en CK-019.5 y
  CK-019.9; no se consideran garantizadas por la interfaz.
- Al editar documentos creados con el esquema anterior, se elimina el campo
  `clientId`. Si existen reseñas antiguas, deben migrarse antes de habilitar su
  lectura pública para evitar exponer ese UID.

## Consultas e índices previstos

- Obtener la reseña de una reserva: lectura directa de
  `reviews/{reservationId}`.
- Listar reseñas públicas del coach: filtro `coachId == <coachUid>` y ordenar
  en la app por `createdAt` descendente.
- La consulta de un solo campo no requiere índice compuesto.

## Resumen de calificación del coach

La colección `reviews` es la fuente canónica para las puntuaciones. El campo
`rating` ya existente en `coaches/{coachId}` no se considera por sí solo una
reseña ni una fuente canónica. El promedio y el conteo se calculan a partir de
las reseñas del coach; el promedio se muestra con un decimal y no se presenta
uno cuando no hay reseñas. No se persiste un agregado duplicado que pueda quedar
desincronizado.

## Fuera del esquema inicial

- Estado de moderación, respuestas del coach y denuncias.
- Datos de pago o referencias a pagos.
- UID, foto o correo del cliente.
- Calificaciones separadas por categorías.
